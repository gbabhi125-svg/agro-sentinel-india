# AgroSentinel — model card (honest findings)

Generated by `ml/training/train.py`. Re-run it and this file's numbers change —
that's intentional; nothing here is hand-edited to look better.

## Data

- `datasets/crop_yield.csv`: 19,652 rows, 55 crops, 30 states, 1997-2020.
  2020 is dropped (37 rows, partial year). Already includes real per-record
  `Annual_Rainfall`, `Fertilizer`, `Pesticide` — used instead of the old
  per-state rainfall guess table.
- `datasets/rainfall in india 1901-2015.csv`: used only to compute each
  state's long-period average (LPA) rainfall for the drought rule (see below).
- 214 rows dropped for exceeding their own crop's 99th-percentile yield
  (implausible data-entry errors — e.g. Maize recorded at 989 t/ha).

## Evaluation method

**Out-of-time**, not random-split: trained on 1997-2016, tested on
2017-2019 (years the model never saw). A random split would let
near-identical rows from the same year leak between train and test, which
is why the old pipeline could report ~100% accuracy on numbers that meant
nothing.

## Yield (regression)

- Test R² = 0.977, pooled MAE = 8.59 (mixes units — see per-crop MAE in
  `ml/registry/v1/metadata.json`, e.g. Wheat ≈0.2-0.3 t/ha, Coconut is in
  nuts/ha and must never be compared against a t/ha crop).
- Per-year R²: 2017=0.983, 2018=0.972, 2019=0.974 — stable across years, not
  a one-off lucky split.

## Crop failure (classification, label = yield < 60% of the crop's own
historical median)

- Does **not** take yield as an input (the old model did — direct leakage,
  since the label is a function of yield).
- Test accuracy 0.895, but the base rate (always predicting "no failure") is
  0.887 — accuracy alone is nearly meaningless here. Precision 0.529, recall
  0.639, F1 0.579: it catches ~64% of real failures, and ~47% of its
  failure warnings are false alarms. Reported to the farmer as exactly that,
  not as a single flattering percentage.

## Season recommendation

- Test accuracy 0.700. Partly high because 14/55 crops are grown in one
  season >=90% of the time historically (Coconut, Sugarcane, Banana, ...) —
  the API suppresses "switch season" advice for those, since it would be
  agronomically meaningless.

## Drought risk — not a trained model

Rainfall departure from each state's long-period average (LPA, computed
from the 1901-2015 series) against simplified-IMD-style thresholds
(Excess/Normal/Deficient/Scanty → Low/Low/Medium/High). This is a rule, not
an ML classifier, because the old label was a direct function of the
feature it was trained on (rainfall in, drought-from-rainfall out — the
model just memorized the threshold and reported ~100% "accuracy"). Dressing
a threshold rule up as an ML model would have been the same dishonesty in a
different shape.

**Known limitation**: subdivision→state mapping for the LPA is an
approximation (several IMD subdivisions merge into one state, unweighted
average); states with no matching subdivision (parts of Rajasthan,
Andaman & Nicobar, Lakshadweep) fall back to the national mean.

## Crop Doctor reasoning engine

Rule-based probabilistic scoring over a curated knowledge base
(`knowledge/causes`, `knowledge/observations`, `knowledge/crops`), not a
trained classifier — every number is traceable to which symptom/weather
signal produced it. Confidence floor 0.35, margin floor 0.12 over the
runner-up, max 3 follow-up questions before either committing or saying
"ask an expert" (see `tests/api/test_reasoning.py` for the ambiguous- and
clear-cut-case tests that pin this behaviour down).

Only 10 of 55 crops (Rice, Wheat, Maize, Cotton, Potato, Onion, Sugarcane,
Groundnut, Soyabean, Banana) have curated named disease/pest profiles
(`knowledge/crops/crop_profiles.json`). Every other crop still gets a
diagnosis, but only at the generic cause level (e.g. "fungal leaf disease"),
and the API says so explicitly rather than inventing a crop-specific name.

## Safety

No entry in the knowledge base names a specific chemical/pesticide —
enforced both at import time (`doctor/safety.py` refuses to start the app
if one is found) and by `tests/api/test_reasoning.py`.
